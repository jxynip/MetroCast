# Phase 4 — Weather Data Collection & Integration

**Objective:** Build a clean, validated and analysis-ready weather dataset that can be seamlessly integrated with the Delhi Metro ridership dataset for both city-wide and regional forecasting.

---

# Step 1 — Define Weather Variables

Identify all weather variables required for forecasting.

### Core Variables
- Rainfall (mm)
- Temperature (°C)
- Relative Humidity (%)

### Optional Variables
- Wind Speed (km/h)
- Cloud Cover (%)
- Surface Pressure (hPa)
- Visibility
- Weather Code

---

# Step 2 — Define Geographic Regions

## City-Wide Model

- Select one representative coordinate for Delhi.

## Regional Extension

Divide the metro network into geographic zones.

Example:

- North Delhi
- South Delhi
- East Delhi
- West Delhi
- Central Delhi
- Noida
- Gurugram/Faridabad

Assign every metro station to exactly one region.

Create:

- Region lookup table
- Station → Region mapping

---

# Step 3 — Download Hourly Weather Data

Using Open-Meteo:

## City Model

Download hourly weather for Delhi.

## Regional Model

Download hourly weather separately for each region.

Requirements:

- Same study period as metro dataset
- Hourly frequency
- Same timezone
- Consistent units

---

# Step 4 — Initial Weather Data Inspection

For every weather dataset:

- Check dimensions
- Inspect column names
- Verify data types
- Examine first and last records
- Confirm hourly continuity

---

# Step 5 — Data Quality Assessment

Perform:

- Missing value analysis
- Duplicate detection
- Timestamp validation
- Outlier inspection
- Unit verification

Ensure:

- No duplicated timestamps
- No unexpected gaps
- Continuous hourly observations

---

# Step 6 — Weather Data Cleaning

- Convert timestamps to datetime
- Standardize timezone
- Rename columns
- Handle missing values
- Remove duplicates
- Correct data types
- Sort chronologically

---

# Step 7 — Create Time Features

Extract:

- Date
- Hour
- Month
- Day of Week
- Business Day / Non-Business Day

These must align perfectly with the metro dataset.

---

# Step 8 — Create Weather Features

Generate variables for later modelling.

Examples:

## Rainfall Features

- Rainfall (Current Hour)
- Rainfall Lag 1 Hour
- Rainfall Lag 2 Hours
- Rainfall Lag 3 Hours

- 3-Hour Rolling Rainfall
- 6-Hour Rolling Rainfall
- 12-Hour Rolling Rainfall

- Cumulative Rainfall

- Rain Event Indicator
- Rainfall Intensity Category
    - No Rain
    - Light
    - Moderate
    - Heavy

---

## Temperature Features

- Temperature
- Temperature Lag
- Rolling Temperature

---

## Humidity Features

- Humidity
- Humidity Lag
- Rolling Humidity

---

# Step 9 — Merge Weather with Metro Data

## City-Wide Dataset

Merge by:

- Date
- Hour

---

## Regional Dataset

Merge by:

- Region
- Date
- Hour

Ensure every metro observation receives the correct weather record.

---

# Step 10 — Validate the Merged Dataset

Verify:

- Row count unchanged
- No duplicate observations
- Weather values correctly assigned
- Missing weather values
- Timestamp alignment
- Region alignment

---

# Step 11 — Post-Merge Quality Checks

Perform sanity checks.

Examples:

- Rainfall varies realistically over time.
- Regional weather differs between regions.
- Rainfall is identical only when expected.
- No impossible temperatures.
- No negative rainfall.

---

# Step 12 — Final Data Preparation

Create two modelling datasets.

## Dataset 1

City-Wide Forecasting Dataset

Contains:

- Metro Features
- Weather Features
- Time Features

---

## Dataset 2

Regional Forecasting Dataset

Contains:

- Metro Features
- Region
- Regional Weather
- Time Features

---

# Deliverables

At the end of Phase 4, the following should be completed:

- Clean city-wide weather dataset
- Clean regional weather datasets
- Station-to-region mapping
- Weather feature engineering
- Fully merged city-wide modelling dataset
- Fully merged regional modelling dataset
- Validated, analysis-ready data for Weather-Based EDA and forecasting
