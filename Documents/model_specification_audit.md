# Forecasting Pipeline Scientific Validity Audit

**Audit date:** 2026-10-14  
**Scope:** `Notebooks/06_Feature_Engineering.ipynb` through `Notebooks/11_Final_Model_Evaluation.ipynb`, prepared datasets, saved Stage 5-8 results, and persisted Stage 7 RF artifacts. No model was fitted and no source notebook, prediction, or metric file was changed during this audit.

## Verdict

**NO-GO for Stage 12 as a realistic, causal, or operational rainfall-impact analysis using isolated rainfall edits.** The existing RF can support a clearly labeled *ceteris paribus model-sensitivity* experiment, but changing `rain_mm` alone while freezing WMO code and other same-hour weather inputs creates feature combinations absent from training. Operational interpretation is additionally blocked by using historical same-hour weather rather than forecast-available weather. Do not present scenario deltas as causal rainfall effects.

## Necessary Corrections Before Stage 12

1. Limit current rainfall scenarios to **exploratory model sensitivity**, not causal or operational impact estimates. Report exactly which features are perturbed and note support/extrapolation for each scenario value.
2. Do not change only `rain_mm` and label the result a realistic weather scenario while holding WMO code and same-hour meteorology fixed. Either explicitly call it a one-feature partial perturbation, or define a coherent joint weather scenario with supported WMO/weather combinations. Keep rainfall-history features fixed only when the intervention is explicitly restricted to the current hour.
3. For operational claims, replace same-hour historical weather with archived forecast weather and evaluate in rolling-origin issue-time order. Keep the stated one-step updating assumption for ridership history; use a separate recursive strategy for multi-step forecasts.
4. Treat 5/10 mm/hour results as low-local-support sensitivity estimates, not well-supported effects. The training set has no values within ±0.5 mm of 5, and only one timestamp within ±0.5 mm of 10; test has no heavy-rain observations. Avoid confidence claims from the sparse rainy strata.
5. Before interpreting model coefficients/splits or scenarios, consider a validation-only robustness model that encodes `weather_code_wmo` as categorical rather than numeric. The current tree pipelines pass it as a numeric feature; this audit does not establish whether that choice changes forecasts.

## Stage 12 Decision

**NO-GO for causal or operational rainfall-impact scenarios with the current data/model inputs.** A narrowly labeled, ceteris-paribus RF sensitivity analysis is permissible as exploratory model behavior only, with joint-feature inconsistency, sparse support, and observed-weather limitations stated prominently. Overall target aggregation, chronology, prior-only feature arithmetic, fair saved metric comparisons, and model artifact integrity pass; the NO-GO is specifically for interpreting isolated rainfall perturbations as realistic/causal or operational effects.
